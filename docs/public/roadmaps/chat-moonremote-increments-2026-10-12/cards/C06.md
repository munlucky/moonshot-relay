# C06 · Claude capability delta 정리

Wave: W1
선행: C05
유형: 구현
초기 상태: NOT_STARTED

## 목표

Claude의 reasoning·delegation·최소 구현 지침을 짧게 정리한다.

## 필요한 입력

- src/host/kernel/provider-prompt-policy.ts
- src/host/kernel/common-model-policy.ts

공통: 해당 선행 카드 결과와 [RUNBOOK](../RUNBOOK.md)의 필요한 부분만 읽는다. 현재 원본이 바뀌었으면 경로를 재확인한다.

## 변경 범위

src/host/kernel/의 Claude policy/prompt와 관련 tests/*.ts.

제품 원본 2~5개와 관련 테스트 1~3개를 기본 크기로 삼는다. 구현 전에 실제 파일 목록을 checkpoint에 고정한다. 위 디렉터리명은 전체 디렉터리를 고칠 허가가 아니다. 새 파일은 기존 구조로 표현 불가능한 경우에만 추가한다.

## 이번 카드에서 할 일

지원 capability에 따라 effort/thinking을 매핑한다. 항상 subagent·항상 자기검증 같은 중복 지침을 제거 후보로 만든다. boundary 검증은 보존한다.

## 완료 조건

- AC-1: 새 execution class와 always-on agent가 없다. 필수 Trust proof는 약화되지 않는다. 미지원 capability는 명시적으로 처리한다.
- AC-2: 내부 fallback 제거 원칙을 외부 입력 검증 삭제로 해석하지 않는다. 미확인 모델 성향은 규칙으로 하드코딩하지 않는다.
- AC-3: 아래 검증의 실제 결과가 현재 source/diff와 연결된다. 미실행 항목을 통과로 기록하지 않는다.
- AC-4: 변경 경로, evidenceRefs, 남은 항목, 다음 카드 ID가 checkpoint와 STATUS에 기록된다.

## 검증

kernel-claude-thinking-policy, kernel-claude-delegation-policy, kernel-common-verification-policy 테스트.

코드 변경이면 현재 build 절차로 테스트 산출물을 갱신한다. 해당 source test를 고치고 생성 진입점을 실행한다. 기존 검사 이름은 실행 시 package/source mapping과 대조한다. 실제 command/receipt가 없는 검증 결과는 인정하지 않는다.

## 범위가 커지거나 중단될 때

다른 독립 동작, 별도 migration, 다수 owner 변경이 필요하면 C06a/C06b로 분리한다. 하위 카드에 목표·선행·허용 파일·AC·검증을 적는다. 테스트가 실패하면 원인을 분류하고 같은 범위의 수정만 수행한다. 무관한 수정은 후속 항목으로 남긴다.

재개 시 기존 taskId/operationId/sessionId와 현재 diff를 먼저 확인한다. 이미 끝난 수정이나 실행을 반복하지 않는다. 이 카드가 완료돼도 다음 카드는 자동 시작하지 않는다.
