# C08 · Prompt Debt 중복 제거와 감사 규칙

Wave: W1
선행: C07
유형: 구현
초기 상태: NOT_STARTED

## 목표

근거가 있는 중복 지침만 제거하고 재검토 조건을 문서화한다.

## 필요한 입력

- src/host/kernel/prompts/common-execution.ts
- tests/kernel-prompt-legacy-instruction.test.ts
- AGENTS.md

공통: 해당 선행 카드 결과와 [RUNBOOK](../RUNBOOK.md)의 필요한 부분만 읽는다. 현재 원본이 바뀌었으면 경로를 재확인한다.

## 변경 범위

C00에서 확정한 canonical prompt/skill 문서 중 최대 5개와 관련 테스트. 설치본 직접 수정 금지.

제품 원본 2~5개와 관련 테스트 1~3개를 기본 크기로 삼는다. 구현 전에 실제 파일 목록을 checkpoint에 고정한다. 위 디렉터리명은 전체 디렉터리를 고칠 허가가 아니다. 새 파일은 기존 구조로 표현 불가능한 경우에만 추가한다.

## 이번 카드에서 할 일

중복 지침별 원본 owner·삭제 이유·남는 authority·대응 eval을 기록한다. major model/공식 지침/tool 구조/token·호출·완료율 변화 시 감사하도록 기존 유지보수 문서에 넣는다.

## 완료 조건

- AC-1: 상시 workflow stage를 만들지 않는다. 모든 삭제는 남는 계약과 연결된다. 적용 profile은 live 평가 전 shadow 또는 기존 off 경로로 보존한다.
- AC-2: 권한·보안·호환성 경계는 긴 문장이라는 이유로 삭제하지 않는다. AGENTS 전체 재작성은 하지 않는다.
- AC-3: 아래 검증의 실제 결과가 현재 source/diff와 연결된다. 미실행 항목을 통과로 기록하지 않는다.
- AC-4: 변경 경로, evidenceRefs, 남은 항목, 다음 카드 ID가 checkpoint와 STATUS에 기록된다.

## 검증

kernel-prompt-legacy-instruction, kernel-prompt-size-budget와 변경한 canonical 자산의 계약 검사.

코드 변경이면 현재 build 절차로 테스트 산출물을 갱신한다. 해당 source test를 고치고 생성 진입점을 실행한다. 기존 검사 이름은 실행 시 package/source mapping과 대조한다. 실제 command/receipt가 없는 검증 결과는 인정하지 않는다.

## 범위가 커지거나 중단될 때

다른 독립 동작, 별도 migration, 다수 owner 변경이 필요하면 C08a/C08b로 분리한다. 하위 카드에 목표·선행·허용 파일·AC·검증을 적는다. 테스트가 실패하면 원인을 분류하고 같은 범위의 수정만 수행한다. 무관한 수정은 후속 항목으로 남긴다.

재개 시 기존 taskId/operationId/sessionId와 현재 diff를 먼저 확인한다. 이미 끝난 수정이나 실행을 반복하지 않는다. 이 카드가 완료돼도 다음 카드는 자동 시작하지 않는다.
