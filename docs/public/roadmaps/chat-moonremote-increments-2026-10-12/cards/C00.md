# C00 · 원격 실행 환경과 선행 작업 기준선

Wave: W0
선행: 없음
유형: 기준/계약/검증
초기 상태: NOT_STARTED

## 목표

Moonremote의 실제 cwd·shell·도구 버전과 Typed Authority 종료 근거를 고정한다.

## 필요한 입력

- AGENTS.md
- package/source-layout.json
- docs/public/development.md
- docs/public/roadmaps/typed-authority-architecture/CURRENT_SOURCE_CLOSURE.md

공통: 해당 선행 카드 결과와 [RUNBOOK](../RUNBOOK.md)의 필요한 부분만 읽는다. 현재 원본이 바뀌었으면 경로를 재확인한다.

## 변경 범위

문서/증거만. 제품 소스와 Moonremote 설정은 변경하지 않는다.

제품 원본 2~5개와 관련 테스트 1~3개를 기본 크기로 삼는다. 구현 전에 실제 파일 목록을 checkpoint에 고정한다. 위 디렉터리명은 전체 디렉터리를 고칠 허가가 아니다. 새 파일은 기존 구조로 표현 불가능한 경우에만 추가한다.

## 이번 카드에서 할 일

원격 경로에서 Git root/HEAD/status와 Node/npm을 확인한다. Windows 경로를 Docker 경로로 추측 변환하지 않는다. 활성 continuity task와 별도 Kernel run 유무를 확인한다. Typed Authority의 기존 종료 증거와 현재 source freshness를 대조한다.

## 완료 조건

- AC-1: 선행 미완료·dirty 변경·도구 누락을 구분한 baseline이 있다. 기존 작업을 삭제하거나 계약을 재발급하지 않는다. 선행 종료 미확인 시 dependent 작업은 BLOCKED다.
- AC-2: 경로 오인·prepared/running/unknown 실행이 있으면 조회부터 한다. Typed Authority 잔여 구현을 이 카드에 합치지 않는다.
- AC-3: 아래 검증의 실제 결과가 현재 source/diff와 연결된다. 미실행 항목을 통과로 기록하지 않는다.
- AC-4: 변경 경로, evidenceRefs, 남은 항목, 다음 카드 ID가 checkpoint와 STATUS에 기록된다.

## 검증

기존 완료 증거 재사용 + git status/rev-parse + npm run build:check. 선행 proof가 없으면 필요한 검증을 별도 작은 카드로 확정한다.

코드 변경이면 현재 build 절차로 테스트 산출물을 갱신한다. 해당 source test를 고치고 생성 진입점을 실행한다. 기존 검사 이름은 실행 시 package/source mapping과 대조한다. 실제 command/receipt가 없는 검증 결과는 인정하지 않는다.

## 범위가 커지거나 중단될 때

다른 독립 동작, 별도 migration, 다수 owner 변경이 필요하면 C00a/C00b로 분리한다. 하위 카드에 목표·선행·허용 파일·AC·검증을 적는다. 테스트가 실패하면 원인을 분류하고 같은 범위의 수정만 수행한다. 무관한 수정은 후속 항목으로 남긴다.

재개 시 기존 taskId/operationId/sessionId와 현재 diff를 먼저 확인한다. 이미 끝난 수정이나 실행을 반복하지 않는다. 이 카드가 완료돼도 다음 카드는 자동 시작하지 않는다.
