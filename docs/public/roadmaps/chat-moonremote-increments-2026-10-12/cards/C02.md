# C02 · 공통 의미 계약과 기존 Envelope 매핑

Wave: W1
선행: C01
유형: 구현
초기 상태: NOT_STARTED

## 목표

기존 필드로 공통 의미 9개를 빠짐없이 전달한다.

## 필요한 입력

- src/host/kernel/prompt-envelope.ts
- src/host/kernel/prompts/common-execution.ts
- src/contracts/host-execution-contract.ts

공통: 해당 선행 카드 결과와 [RUNBOOK](../RUNBOOK.md)의 필요한 부분만 읽는다. 현재 원본이 바뀌었으면 경로를 재확인한다.

## 변경 범위

src/host/kernel/prompt-envelope.ts; src/host/kernel/prompts/common-execution.ts; 관련 tests/*.ts. wire schema는 필요가 입증된 경우만.

제품 원본 2~5개와 관련 테스트 1~3개를 기본 크기로 삼는다. 구현 전에 실제 파일 목록을 checkpoint에 고정한다. 위 디렉터리명은 전체 디렉터리를 고칠 허가가 아니다. 새 파일은 기존 구조로 표현 불가능한 경우에만 추가한다.

## 이번 카드에서 할 일

CONTRACTS의 P 계약을 기존 goal/context/constraints/doneWhen과 매핑한다. 의미 원본을 하나로 유지한다. 기존 DTO에 정보가 있으면 새 schema를 만들지 않는다.

## 완료 조건

- AC-1: objective·acceptance·work unit·scope·knowledge·verification·tools·mutation authority·completion이 보존된다. 모델명과 provider 문체가 Kernel에 추가되지 않는다.
- AC-2: 필드 누락/잘못된 타입을 조용히 빈 문자열로 통과시키지 않는다. schema migration이 필요하면 먼저 별도 카드로 분리한다.
- AC-3: 아래 검증의 실제 결과가 현재 source/diff와 연결된다. 미실행 항목을 통과로 기록하지 않는다.
- AC-4: 변경 경로, evidenceRefs, 남은 항목, 다음 카드 ID가 checkpoint와 STATUS에 기록된다.

## 검증

kernel-common-execution-prompt, kernel-prompt-envelope, kernel-host-semantic-conformance 관련 테스트.

코드 변경이면 현재 build 절차로 테스트 산출물을 갱신한다. 해당 source test를 고치고 생성 진입점을 실행한다. 기존 검사 이름은 실행 시 package/source mapping과 대조한다. 실제 command/receipt가 없는 검증 결과는 인정하지 않는다.

## 범위가 커지거나 중단될 때

다른 독립 동작, 별도 migration, 다수 owner 변경이 필요하면 C02a/C02b로 분리한다. 하위 카드에 목표·선행·허용 파일·AC·검증을 적는다. 테스트가 실패하면 원인을 분류하고 같은 범위의 수정만 수행한다. 무관한 수정은 후속 항목으로 남긴다.

재개 시 기존 taskId/operationId/sessionId와 현재 diff를 먼저 확인한다. 이미 끝난 수정이나 실행을 반복하지 않는다. 이 카드가 완료돼도 다음 카드는 자동 시작하지 않는다.
