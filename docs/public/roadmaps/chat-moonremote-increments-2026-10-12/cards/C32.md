# C32 · 전체 계약 추적과 통합 검증

Wave: 마감
선행: C29 및 C30/C31의 조건 처리
유형: 기준/계약/검증
초기 상태: NOT_STARTED

## 목표

계획 전체의 완료·제외·미완료를 구분하고 통합 결과를 닫는다.

## 필요한 입력

- STATUS.md
- CONTRACTS.md
- docs/public/development.md

공통: 해당 선행 카드 결과와 [RUNBOOK](../RUNBOOK.md)의 필요한 부분만 읽는다. 현재 원본이 바뀌었으면 경로를 재확인한다.

## 변경 범위

계획 ledger·기존 통합 검증·임시 설치 증거. 제품 기능 추가 금지.

제품 원본 2~5개와 관련 테스트 1~3개를 기본 크기로 삼는다. 구현 전에 실제 파일 목록을 checkpoint에 고정한다. 위 디렉터리명은 전체 디렉터리를 고칠 허가가 아니다. 새 파일은 기존 구조로 표현 불가능한 경우에만 추가한다.

## 이번 카드에서 할 일

각 카드 AC와 receipt/diff digest를 대조한다. 영향받은 Kernel/Host/Knowledge 통합·package suite를 필요한 범위로 실행한다. 외부 평가와 플랫폼 미검증을 별도로 표시한다.

## 완료 조건

- AC-1: 필수 카드 31개가 완료이고 W10 2개는 완료 또는 합리적 제외다. complexity budget 위반이 없다. Kernel 사용 run은 실제 next.action.type=done 근거가 있어야 Kernel 완료라고 보고한다.
- AC-2: 미통과를 문서 서술로 덮지 않는다. commit/push/계정 설치는 별도 요청이 있을 때 별도 카드로 수행하며 상세 한국어 메시지와 parity 증거를 남긴다.
- AC-3: 아래 검증의 실제 결과가 현재 source/diff와 연결된다. 미실행 항목을 통과로 기록하지 않는다.
- AC-4: 변경 경로, evidenceRefs, 남은 항목, 다음 카드 ID가 checkpoint와 STATUS에 기록된다.

## 검증

적용 범위에 맞는 typecheck/build/boundaries/test:kernel/test:package/test:eval. 이미 같은 digest에서 통과한 중복 검증은 반복하지 않는다.

코드 변경이면 현재 build 절차로 테스트 산출물을 갱신한다. 해당 source test를 고치고 생성 진입점을 실행한다. 기존 검사 이름은 실행 시 package/source mapping과 대조한다. 실제 command/receipt가 없는 검증 결과는 인정하지 않는다.

## 범위가 커지거나 중단될 때

다른 독립 동작, 별도 migration, 다수 owner 변경이 필요하면 C32a/C32b로 분리한다. 하위 카드에 목표·선행·허용 파일·AC·검증을 적는다. 테스트가 실패하면 원인을 분류하고 같은 범위의 수정만 수행한다. 무관한 수정은 후속 항목으로 남긴다.

재개 시 기존 taskId/operationId/sessionId와 현재 diff를 먼저 확인한다. 이미 끝난 수정이나 실행을 반복하지 않는다. 이 카드가 완료돼도 다음 카드는 자동 시작하지 않는다.
